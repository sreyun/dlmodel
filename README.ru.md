**dlmodel — это self-hosted менеджер загрузки весов LLM-моделей**: в условиях ограниченной сети он надёжно скачивает модели с ModelScope / Hugging Face за счёт перебора нескольких источников и многопоточной загрузки через aria2, сохраняет их в раскладке vLLM, а web-интерфейс управляет очередью, докачкой и паузой/возобновлением — после завершения загрузки модели подаются напрямую в vLLM / Ollama.

## Возможности

- 🔄 **Автоматический перебор источников** — режим `auto` сначала пробует ModelScope, затем зеркало HF; внутри каждого источника идёт поэтапная деградация: **aria2 (много соединений) → однопоточный HTTP с докачкой → нативный SDK**, прямое подключение к hf-mirror.com / ModelScope без прокси
- ⏸️ **Пауза / возобновление / докачка** — состояние `paused` является полноценным: это корректная остановка сетевого потока, а не отмена; сохраняются запись задачи, прогресс, загруженные файлы, точки докачки и логи. Возобновление продолжает с точки остановки (aria2 `continue` / HTTP `Range` / `.temp` SDK / серверный кэш Ollama)
- 📊 **Очередь загрузок** — параллельные задачи (1–8), много соединений на файл, прогресс / скорость / ETA (полный размер берётся из метаданных источника; если его определить не удаётся, честно показывается «неизвестно», а не поддельный процент), повторные попытки при сбоях с экспоненциальной задержкой для временных TLS/сетевых ошибок
- 🛡️ **Корректная перезагрузка** — при остановке все задачи `queued` / `running` сохраняются в SQLite и автоматически возвращаются в очередь при следующем запуске; обновления и перезапуски не теряют задачи
- 🔑 **Bearer-токен** — сравнение за constant time + стартовый гейт (слишком короткий или слабый токен запрещает запуск) + ограничение частоты неудачных попыток авторизации (429)
- 🤖 **Интеграция с инференсом** — Compose-профили для Ollama / vLLM в одну команду; UI генерирует команду запуска vLLM по пути скачанной модели (путь + порт, безопасное экранирование); сканирование библиотеки моделей, список и pull локальных моделей Ollama
- 📱 **Уведомления в чат-ботов** — DingTalk / Feishu (Lark) / WeCom, переключатели по событиям, белый список адресов отправки, маскирование токенов при отображении
- 🗃️ **Без внешних зависимостей** — задачи и настройки хранятся в SQLite (WAL); `docker compose up -d` — это полностью развёрнутое приложение (без БД, брокера сообщений и Node-сборки)

**Технологии**: FastAPI + uvicorn + httpx (async) · aria2 JSON-RPC · aiosqlite · запасные варианты через huggingface_hub / modelscope SDK · SPA на нативном JS без сборки (без внешних ресурсов, полностью закрытая CSP)

## Быстрый старт

Работает на Linux / macOS / Windows.

```bash
# 1. Клонирование
git clone https://github.com/sreyun/dlmodel.git
cd dlmodel

# 2. Настройка (ключевой шаг: задайте стойкий ADMIN_TOKEN)
cp .env.example .env        # Windows PowerShell: Copy-Item .env.example .env
python -c "import secrets; print(secrets.token_urlsafe(32))"   # сгенерируйте токен и запишите в .env

# 3. Запуск (по умолчанию используются образы с ускорением Huawei SWR;
#    если ваша организация SWR приватная — сначала docker login swr.cn-east-3.myhuaweicloud.com)
docker compose up -d

# 4. Откройте браузер и войдите по ADMIN_TOKEN
#    http://<ip-сервера>:8080
```

После входа создайте задачу загрузки (источник `auto`, цель `vLLM`); по завершении путь к файлам отображается в карточке задачи (и на странице библиотеки моделей) — его можно передать в vLLM / Ollama.

> ⚠️ **Безопасность**: по умолчанию web-интерфейс слушает `0.0.0.0:8080`. Перед выходом в публичную сеть обязательно задайте длинный случайный `ADMIN_TOKEN` в `.env` (токен короче 12 символов или из списка слабых **запретит запуск сервиса**) и поставьте приложение за обратный прокси / HTTPS. `ARIA2_RPC_SECRET` также замените на уникальное значение.

## Архитектура

```
Браузер SPA (frontend/, нативный JS без сборки, короткий polling)
   │  Bearer-токен
   ▼
Маршруты FastAPI ── /api/downloads* /api/settings /api/models /api/services/* /api/health
   │
   ├─ DownloadQueue: пул asyncio-воркеров (параллелизм 1–8), машина состояний
   │     queued → running → completed | failed | cancelled
   │        ▲ пауза (корректная остановка потока, прогресс и точки докачки сохраняются)
   │        └──── paused ◄────┘──► возобновление → queued, докачка
   │
   ├─ Загрузчики: source auto → ModelScope ⇁ зеркало HF; внутри источника aria2 → HTTP Range → SDK
   ├─ Plane управления: кооперативные cancel / pause (сигналы проверяются в on_progress / on_log,
   │        не поглощаются повторами и откатами)
   ├─ Контейнер aria2 (JSON-RPC, 16 соединений на файл, докачка через .aria2-контрол-файлы)
   └─ SQLite (WAL): tasks + settings; queued/running паркуются при остановке, перечитываются при старте
Тома: ./data/models (веса, общие с vLLM/Ollama) · ./data/app (БД) · ./data/aria2
```

Целостность состояний обеспечивается CAS-обновлениями (`UPDATE … WHERE status IN (…)`): при любом пересечении паузы / возобновления / отмены между queued и running побеждает ровно одна сторона; воркер перед отправом перепроверяет владение задачей. Терминальные состояния и пауза единообразно освобождают всю память учёта (флаги отмены/паузы, map gid aria2, наборы дедупликации уведомлений) — утечек при длительной работе нет.

## Справочник конфигурации

Вся конфигурация задаётся в `.env` в корне репозитория (значения по умолчанию в скобках):

| Переменная | По умолчанию | Описание |
|------------|--------------|----------|
| `ADMIN_TOKEN` | `changeme` | Bearer-токен UI / API — **обязательно замените**; <12 символов или слабый → запуск запрещён |
| `MODEL_ROOT` | `/models` | Корень весов моделей (compose: `./data/models`) |
| `DATA_DIR` | `/data` | SQLite `app.db` и настройки (compose: `./data/app`) |
| `HF_ENDPOINT` | `https://hf-mirror.com` | Адрес зеркала HF |
| `HF_TOKEN` | пусто | Для gated-моделей (зеркало должно поддерживать проброс токена) |
| `MODELSCOPE_API_TOKEN` | пусто | Токен ModelScope |
| `ARIA2_RPC_URL` | `http://aria2:6800/jsonrpc` | Адрес RPC-панели aria2 |
| `ARIA2_RPC_SECRET` | `dlmodel` | Должен совпадать с сервисом aria2; в проде обязательно заменить |
| `DOWNLOAD_CONCURRENCY` | `2` | Число параллельных задач (горячая регулировка 1–8 через API) |
| `ARIA2_CONNECTIONS` | `16` | Соединений на файл |
| `DOWNLOAD_RETRIES` | `3` | Повторы временных TLS/сетевых ошибок (экспоненциальная задержка; 0 = выкл) |
| `OLLAMA_BASE_URL` | `http://ollama:11434` | Адрес Ollama (профиль или удалённый) |
| `VLLM_BASE_URL` | `http://vllm:8000` | Адрес vLLM (профиль или удалённый) |
| `VLLM_MODEL` | пусто | **Конкретный скачанный путь репозитория** для `--profile vllm` |
| `NOTIFY_DINGTALK_WEBHOOK` / `NOTIFY_FEISHU_WEBHOOK` / `NOTIFY_WECOM_WEBHOOK` | пусто | Webhook чат-ботов (настройки из UI приоритетнее) |
| `NOTIFY_ON_COMPLETED` / `NOTIFY_ON_FAILED` | `1` | Переключатели: завершено / ошибка |
| `NOTIFY_ON_STARTED` / `NOTIFY_ON_CANCELLED` | `0` | Переключатели: начато / отменено |
| `DLMODEL_IMAGE` | SWR `:latest` | Прод-образ; для отката зафиксируйте `:vX.Y.Z` |
| `ARIA2_IMAGE` | `p3terx/aria2-pro` через SWR | Образ aria2 (с v0.4.1 по умолчанию адрес с ускорением SWR, загрузка без прокси) |
| `WEB_BIND` / `WEB_PORT` | `0.0.0.0` / `8080` | Привязка и порт web-интерфейса |
| `PUID` / `PGID` | `0` / `0` | Идентификатор aria2; должен совпадать с правами на том моделей |

`HF_TOKEN` / `MODELSCOPE_API_TOKEN`, сохранённые на странице настроек (в SQLite), имеют приоритет над одноимёнными переменными окружения и могут меняться «на горячую».

## Обзор API

Все конечные точки, кроме `GET /api/health`, требуют `Authorization: Bearer <ADMIN_TOKEN>`.

| Метод и путь | Описание |
|--------------|----------|
| `POST /api/downloads` | Создать задачу. Тело `{name, source: auto\|modelscope\|huggingface\|ollama, target: vllm\|ollama, revision?}`; `400`, если уже есть активная задача (включая `paused`) с тем же именем и целью |
| `GET /api/downloads` | Список задач (включая `progress_bytes` / `total_bytes` / `speed_bps`) |
| `GET /api/downloads/{id}` | Одна задача |
| `POST /api/downloads/{id}/pause` | Пауза задачи `queued` / `running` (`400` — недопустимое состояние) |
| `POST /api/downloads/{id}/resume` | Возврат задачи `paused` в очередь |
| `POST /api/downloads/{id}/cancel` | Отмена (из активных состояний и из `paused`) |
| `POST /api/downloads/{id}/retry` | Повтор `failed` / `cancelled`: возврат в очередь и продолжение с точки докачки |
| `DELETE /api/downloads/{id}` | Удалить запись задачи (терминальные и `paused`; только запись, файлы остаются) |
| `POST /api/downloads/cleanup?status=…` | Пакетная очистка терминальных записей (по умолчанию `completed,cancelled,failed`) |
| `GET /api/downloads/{id}/events` | SSE-поток прогресса (только Bearer-заголовок, см. [FAQ](#faq--устранение-неполадок) №4) |
| `GET` / `PUT /api/settings` | Чтение / запись настроек (токены и webhooks маскируются; PUT применяет только ненулевые поля) |
| `POST /api/settings/notify-test` | Отправить тестовое уведомление |
| `GET /api/models` · `DELETE /api/models/{id}` | Сканирование библиотеки (путь / размер) и удаление (**удаляет каталог модели с диска**; удаление записей задач файлы не трогает) |
| `GET /api/services/ollama/health` · `…/models` · `POST …/pull` | Ollama: здоровье, список локальных моделей, pull (с переопределением tag) |
| `GET /api/services/vllm/health` · `…/launch-command` | vLLM: здоровье, генерация команды запуска |
| `POST /api/auth/verify` | Проверка токена |
| `GET /api/health` | Liveness-проба (без авторизации, для container healthcheck) |

Горячее изменение параллелизма: `PUT /api/settings` с `download_concurrency` немедленно вызывает `resize` очереди (1–8).

## Развёртывание и образы

- **Продакшен**: `docker compose up -d` — образ по умолчанию `swr.cn-east-3.myhuaweicloud.com/sreyun/dlmodel:latest` (образ aria2 тоже через SWR-ускорение); `pull_policy: always` обновляет образ при каждом `up`; для фиксации версии или отката задайте `DLMODEL_IMAGE=…:vX.Y.Z` в `.env`
- **Релизный CI**: push тега `v*` запускает GitHub Actions «Build and push Huawei SWR», обновляя `:<tag>` и `:latest`; требуются Secrets `HW_ACCESS_KEY` / `HW_SECRET_KEY` (опционально Variable `HW_SWR_NAMESPACE`, по умолчанию `sreyun`), организацию заранее создайте в [консоли SWR](https://console.huaweicloud.com/swr) (регион cn-east-3); ручной перезапуск: Actions → Run workflow

### Опциональные инференс-сервисы

Управление и загрузка не зависят от инференса; включайте его Compose-профилями по мере надобности (по умолчанию выключены):

```bash
docker compose --profile ollama up -d      # локальный API: http://127.0.0.1:11434
docker compose --profile vllm up -d        # OpenAI-совместимый: http://127.0.0.1:8000, нужен NVIDIA Container Toolkit
```

- `VLLM_MODEL` должен указывать на **конкретный скачанный путь репозитория** (например `/models/hf/Qwen/Qwen3-0.6B`), а не на корень `/models/hf`; запишите его в `.env` после завершения загрузки и пересоздайте `vllm`
- vLLM по умолчанию использует образ `vllm/vllm-openai:latest` + `runtime: nvidia`; `HUGGING_FACE_HUB_TOKEN` пробрасывается из `HF_TOKEN`
- Модели, загруженные через Ollama, хранятся в `{MODEL_ROOT}/ollama` (монтируется как `/root/.ollama`) и общие с источником Ollama на странице загрузок

## FAQ / Устранение неполадок

**1. aria2 недоступна / качается только в одно соединение?**
При сбое RPC загрузчик автоматически деградирует до однопоточного HTTP с докачкой (в сообщении задачи — «aria2 недоступна»), загрузка при этом продолжается. Причин отсутствия многопоточности обычно две: **сеть** или **права доступа**. Значения по умолчанию `PUID=0` / `PGID=0` существуют именно для обхода проблем записи в общий том; при слишком строгих правах на хост-каталоги aria2 не может писать `.aria2`-файлы и том моделей — дайте пользователю контейнера запись в `./data/models` и `./data/aria2`. После исправления перезапустите загрузку: если сообщение «aria2 недоступна» исчезло — восстановлено; состояние контейнера видно в `docker compose ps` / `docker compose logs aria2`.

**2. HF-модель отдаёт 401 / 403 (gated)?**
Задайте `HF_TOKEN` (примите условия модели на HF и сгенерируйте токен) на странице настроек или в `.env` и убедитесь, что используемое зеркало поддерживает проброс токена (hf-mirror.com поддерживает). Для моделей, доступных только на ModelScope, используйте `auto` или явный источник `modelscope`.

**3. После нажатия «Продолжить» — «для этой цели уже идёт загрузка»?**
Это известное ограничение ModelScope: `snapshot_download` выполняется в блокирующем потоке, который нельзя прервать мгновенно, поэтому пауза реализована как «прекратить слежение и припарковать в `paused`», а целевой каталог освобождается после завершения фонового потока. **Мгновенное возобновление той же цели отклоняется (409) во избежание параллельной двойной записи** — подождите немного и нажмите «Продолжить» снова. Все остальные источники (HF / aria2 / HTTP / Ollama) возобновляются сразу.

**4. Зачем polling, если есть SSE?**
`GET /api/downloads/{id}/events` принимает Bearer-токен только в заголовке запроса, а нативный браузерный `EventSource` не умеет задавать кастомные заголовки — поэтому UI использует короткий polling (1 с активный / 4 с простойный). Для realtime-push интегрируйте `fetch` + ReadableStream самостоятельно.

**5. Порт уже занят?**
Измените `WEB_PORT` в `.env` (а также `WEB_BIND` для адреса привязки) и выполните `docker compose up -d` повторно.

**6. Мало места на диске (No space left on device)?**
Причина выводится в сообщении задачи и в уведомлении. Важно: **ошибки переполнения диска и отказа прав не повторяются автоматически** (повтор бессилен). Освободите место и нажмите «Повторить» — загрузка продолжится с точки докачки. Перед загрузкой десятков гигабайт проверяйте место через `df -h`.

**7. Куда деваются задачи running после перезапуска контейнера?**
При старте очередь единообразно возвращает в очередь все задачи `queued` / `running` и перепланирует их (сообщение «Перепоставлено в очередь после перезапуска…», охватывает и корректное завершение, и жёсткую остановку вроде `docker compose down`); aria2 восстанавливает незавершённые передачи, HTTP / SDK продолжают по дисковым точкам докачки. Задачи `paused` перезапуск переносят без изменений и ждут вашего нажатия «Продолжить».

**8. Задача постоянно падает — как узнать почему?**
Поле `message` каждой задачи показывает причину ошибки или текущую стадию (разбор источника, откат, номер повтора), доступно через `GET /api/downloads/{id}`; серверные логи (`docker compose logs web`, формат JSON) содержат полную хронологию с ID задач, токены маскируются.
